# 2D 工作流

引擎里 **2D 不是「3D 相机换成正交」**，而是一等公民：场景带维度、有独立的渲染路径、
有专门的编辑器视口和独立的示例程序。这一页是 2D 的全部使用姿势。

## 场景维度（2D / 3D）

```cpp
scene->SetDimension(SceneDimension::Scene2D);  // 或 Scene3D（默认）
scene->Is2D();                                 // 渲染路径 / 编辑器面板 / Launch 目标都由它决定
```

- 维度随场景文件保存为顶层 `"dimension": "2d" | "3d"`；旧文件没有该字段时按「主相机是否正交」推断。
- `SetDimension(Scene2D)` 会一并应用 2D 默认值（关天空盒 / SSAO / TAA / Bloom / God Rays / IBL，
  背景若仍是纯黑则换成深蓝灰）——因为 2D 路径**根本不执行**这些 3D 阶段。
- 切换维度不需要动相机：`Scene::EnsurePrimaryCamera2D(ortho_size = 6, z = 10)` 保证存在一个正交主相机。

## 渲染路径

| | 2D 场景 | 3D 场景 |
| --- | --- | --- |
| 入口 | `Scene::Render2D` | `Scene::RenderMeshes` |
| 内容 | 只有 `SpriteComponent` | 网格 / 模型 / 精灵（半透明通道） |
| 阶段 | 一次清屏 + 精灵实例化批次 | 阴影 → 点光阴影 → SSAO → 主 pass(HDR) → 天空盒 → 后处理 |
| 颜色 | 直接写目标帧缓冲，无 tone mapping | ACES/gamma 等后期 |
| 排序 | sorting layer → order in layer → z | 不透明按材质合批，半透明按层/距离 |

两条路径由 `Scene::RenderFromPrimaryCamera()`（编辑器 Play / sandbox 的唯一入口）按维度自动分派。
细节见 [rendering.md](./rendering.md) 的「2D 场景」一节。

## 精灵组件

```cpp
Entity fox = scene->CreateEntity("Fox");
auto &t = fox.AddComponent<Transform>();
t.translation = glm::vec3(-2.0f, -1.0f, 0.0f);

auto &sprite = fox.AddComponent<SpriteComponent>(AssetManager::Instance().GetTexture("textures/qoguldsd.png"));
sprite.FitPixels(SpriteSheet{6, 1}, 32.0f);  // 按 32 px/unit 定尺寸，不拉伸帧像素
sprite.sorting_layer = 0;                    // 越大越靠前
sprite.order_in_layer = 0;                   // 同层内再排序
```

| 字段 / 方法 | 说明 |
| --- | --- |
| `texture` / `color` | albedo（为空则是纯色四边形）+ tint（rgb + 透明度） |
| `uv_rect` | 归一化 `(u0,v0,u1,v1)` 子矩形；`SetSheetFrame` / `SetWholeTexture` 维护它 |
| `size` | 世界单位尺寸（`Transform.scale` 再乘一层，方便父子缩放） |
| `tiling` | 贴图在四边形上重复几次（见下方「平铺」） |
| `flip_x` / `flip_y` | 镜像；Lua 里用 `self:set_sprite_flip_x(true)` |
| `sorting_layer` / `order_in_layer` | 绘制顺序（painter），同层内相同 order 时按世界 z |
| `FitPixels(sheet, px_per_unit)` | 按贴图/帧像素尺寸定 `size`（常用 32 或 100 px = 1 单位） |
| `SetTiledSize(world_size, px_per_unit)` | 定 `size` 并让贴图按自身尺寸重复，保证纹素是方的 |

## 精灵帧动画

`SpriteSheet` 把一张贴图切成网格，帧 0 在**左上角**，`SpriteAnimationComponent` 每帧把当前帧写回
精灵的 `uv_rect`（`Scene::StepSimulation` 里统一推进；编辑器 Edit 模式下 2D 场景也会预览）：

```cpp
const SpriteSheet sheet{6, 1};  // 6 列 1 行 = 6 帧横向走路循环
sprite.SetSheetFrame(sheet, 0);
auto &anim         = fox.AddComponent<SpriteAnimationComponent>();
anim.sheet         = sheet;
anim.fps           = 8.0f;
anim.loop          = true;
anim.play_while_moving = true;  // 走路循环模式：只在实际移动时播，停下回第 0 帧
```

- `first_frame` / `frame_count` 让「一张图多段动画」共用贴图（例如第 0 行走路、第 1 行待机）。
- `playing` 是总开关；`play_while_moving` 打开后**移动实体的代码不需要管动画**：
  `Scene::UpdateSpriteAnimations` 每帧比较世界坐标，动过才推进，停下就 `Reset()` 回待机帧。
- 实例：`assets/scripts/fox_controller.lua`（WASD 移动 + 按方向转身）挂在演示场景的 Fox 上。

## 平铺（重复背景）

`tiling` 被烘进 sprite 四边形的 UV（采样器是 `GL_REPEAT`），所以**纹素不会被拉伸**：

```cpp
// 30x18 单位的背景，铺 64x64 的棋盘贴图 → 每 2 单位重复一次，格子始终是方的
background.SetTiledSize(glm::vec2(30.0f, 18.0f), 32.0f);
```

只用 `size` 贴一张方形贴图去铺 30×18 的地面，格纹就会变成 1.64:1 的长方形——这正是「背景方块不是方的」
的成因。检查器里有 `Tiling` 滑条和 `Tile at 32 px/unit` 一键按钮。

> 注意：`uv_rect` + 平铺 = 重复「选中的那一帧」；图集无缝平铺需要 shader 端按子矩形取模（尚未实现）。

## 用 Lua 控制角色

```lua
function OnUpdate(dt)
  local dx = 0.0
  if MEngine.is_key_down("a") or MEngine.is_key_down("left") then dx = -1.0 end
  if MEngine.is_key_down("d") or MEngine.is_key_down("right") then dx = 1.0 end

  local x, y, z = self:get_position()
  self:set_position(x + dx * 3.0 * dt, y, z)

  if dx < 0.0 then self:set_sprite_flip_x(true) elseif dx > 0.0 then self:set_sprite_flip_x(false) end
end
```

可用的 API：`MEngine.is_key_down/time/delta_time/log/find_entity/...`，实体上的
`get_position/set_position`、`get_rotation/set_rotation`、`get_scale/set_scale`、
`set_sprite_flip_x/get_sprite_flip_x`、`get_color/set_color`、物理相关 `get_velocity/set_velocity/apply_impulse` 等。

## 编辑器里的 2D

- **File → New 2D Scene**：建正交主相机 + 平铺棋盘背景 + 6 帧狐狸走路动画（带控制器脚本）+ 静态精灵。
- **2D Viewport** 面板（独立于 3D 视口）：`Sprite` 新建、`Frame All` 取景、`Launch` 起独立播放器；
  中键平移、滚轮缩放；从内容浏览器**拖入图片 = 用该贴图新建精灵**。
- `Sprite (2D)` / `Sprite Animation (2D)` 检查器覆盖上表所有字段；Info 面板在 2D 下显示
  `Center (X/Y)` + `Zoom size`。
- 详见 [editor.md](./editor.md)。

## 独立运行

```bash
# 编辑器里按 Launch，或直接跑：
sandbox2d --scene <path/to/scene.scene>     # 2D 场景
sandbox3d --scene <path/to/scene.scene>     # 3D 场景
sandbox2d                                    # 无参数则跑内置 2D 演示（地砖 + 玩家 + 宝石 + 狐狸）
```

`sandbox2d` 无参数演示：方向键移动狐狸（`play_while_moving` 驱动走路循环）、WASD 移动玩家精灵并跟随相机。
另外支持 `MENGINE_SANDBOX2D_AUTOMOVE=<秒>` 做无头验证（自动前进 N 秒后停下，日志里能看到
`playing=yes/frame=…` 变到 `playing=no/frame=0`）。

## 已知边界

- 2D 场景不绘制 `MeshComponent` / `ModelComponent`（走精灵通道）；要 3D 内容就建 3D 场景。
  3D 场景里的精灵仍然会画（走 3D 半透明通道，带 tone mapping）。
- 合批只在**连续区间**内合并相同 quad + 相同材质内容的精灵（跨 sorting layer 不合并）。
- 还没有 tilemap / 图集打包 / 九宫格；2D 没有专用物理（Jolt 是 3D 体，可用平面运动脚本代替）；
  精灵没有 pivot/锚点（旋转绕四边形中心）。
